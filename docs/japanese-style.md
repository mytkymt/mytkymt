# 日本語ページの編集方針

2026年9月16日と10月4日の指定に基づきます。本文は丁寧語で統一します。論文翻訳と紹介文では以下の方針を共通して用います。

## 文を組み立てます

- 一文では一つの話題を扱い、説明の関係が自然に伝わる長さに整えます。原因と結果や操作と目的は同じ文でつなぎ、話題が変わる箇所で文を分けます。
- 修飾語を対象の近くに置きます。主語は動作や主体の区別に必要な箇所で明示します。
- 語順と文の分割で意味を明確にしてから必要な読点を加えます。「また」「そこで」「本研究では」の直後には自動的に読点を置きません。
- 意味のつながる短文は「〜し」「〜ため」「〜ことで」などを用いて自然につなぎます。接続詞を増やすだけでなく、重複する主語や述語を整理して段落全体の流れを整えます。
- 並列する短い名詞には中黒を利用できます。長い列挙は分類するか文を分けます。中黒や「と」「や」の連続によって読みにくさを移すだけの修正は避けます。
- 見出しや図表ラベルは名詞でも構いません。説明文は述語で終えます。

## 段落を展開します

- 研究紹介の冒頭では何を実現する研究かを示します。続いて課題・方法・実現できることを説明します。
- 方法の説明では対象と操作を先に置きます。次にその操作が必要な理由や得られる機能を述べます。
- 長い説明では最初に全体像を示します。その後に項目ごとの方法と評価を説明します。
- 「そこで」は課題から方法へ進むときに使います。「これにより」は直前の方法から帰結を説明するときに使います。接続詞を入れる前に論理関係を確認します。
- 各段落の冒頭と末尾を対応させます。冒頭で示した課題に対して何が分かったかを末尾で明確にします。

## 用語を選びます

- 「対象を制御する」「システムを構築する」「試料を作製する」「特性を評価する」など対象と動作を具体的に記します。
- 物を作る場合は「作製」を用います。文書やデータを作る場合は「作成」を用います。システムやモデルには内容に応じて「構築」「開発」「生成」を使います。
- 技術名を示した後に何をする技術かを説明します。食品内部の構造や成分分布など読者が具体的に捉えられる対象を示します。
- 同じ対象には同じ名称を使います。技術本文では原則として「ユーザ」「プリンタ」「インタフェース」に表記を統一します。
- 知覚・嗜好・物性・性能を区別します。測定した結果と解釈と今後の可能性を区別して述べます。

## 論文翻訳に適用します

- 原文の章構成と主張の範囲を保ちます。段落内の語順や文の切り方を整えます。
- 数値・単位・数式・引用・実験条件・否定・留保を保持します。接続詞によって原文にない因果関係を作らないよう確認します。
- 著者名と原著タイトルと参考文献は原文を保持します。
- AIによる翻訳であることを明記します。詳細を確認できる正式版へのリンクを添えます。

## 適用範囲を確認します

この方針には本人の明示的な指定と参考文章から抽出した傾向が含まれます。参考文章の傾向は今後のフィードバックに応じて調整します。申請書特有の主張の強さや将来計画の語尾は公開済み論文へ機械的に適用しません。

読点の役割の確認には[国立国語研究所の解説](https://kotoba.ninjal.ac.jp/qa/yokuaru/qa-53/)を参照します。本サイトでは語順の調整と文の分割を優先します。
